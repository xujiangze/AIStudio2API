# 首字竞速与短冷却设计

状态：功能已实现并通过离线回归，发布标签为 `v0.3.13-xjz-20261122.1`。本文描述实现及其适用边界；线上仍需拉取新构建并重启才会生效。

## 目标与取舍

优先降低生成请求的首字延迟，避免一次尝试长时间卡住而没有其他账户参与服务。用户接受备用请求带来的额外额度消耗，以更多账户支撑容量。

本次只处理首事件之前的等待，不处理已经开始输出后的流中停顿，不在输出已交给客户端后从头换号生成。正常但首事件很慢的长思考、长上下文请求也可能被首字总期限停止，这是已接受的延迟与成功率取舍。

术语见 [GLOSSARY.md](../GLOSSARY.md)。这里沿用现有“首字”名称，其准确含义是第一个非错误上游事件，不保证是第一个可见正文字符。

## 参数与开关

本次采用以下初始参数，均可在设置中调整：

| 参数 | 配置键 | 初始值 | 关闭方式或范围 |
| --- | --- | --- | --- |
| 首字竞速 | `FIRST_EVENT_HEDGE` | 自定义 20 秒 | 复用现有关闭 / 自动 / 自定义设置 |
| 竞速模型 | `FIRST_EVENT_HEDGE_MODELS` | `*`，全部符合条件的模型 | 空列表仍表示未选择模型 |
| 全局备用并发上限 | `FIRST_EVENT_HEDGE_MAX_CONCURRENCY` | 16 | 仍受各账户并发上限约束 |
| 首字总等待上限 | `FIRST_EVENT_TIMEOUT_SECONDS` | 60 秒 | 0 表示关闭 |
| 竞速冷却 | `FIRST_EVENT_RACE_COOLDOWN_SECONDS` | 30 秒 | 0 表示关闭 |
| 繁忙冷却 | `MODEL_BUSY_COOLDOWN_SECONDS` | 10 秒 | 0 表示关闭 |

竞速、首字总等待上限、繁忙冷却独立控制。关闭竞速只禁止启动备用请求，因此也不再产生新的竞速冷却；首字总期限与繁忙冷却仍按各自设置生效，已有冷却不因关闭开关而自动解除。

“全部模型”使用明确的配置表达；旧配置中的空模型列表仍表示未选择模型，不改成全选。已有显式关闭或指定模型配置不在升级时被静默覆盖。

## 适用范围

首字竞速与首字总等待上限采用同一类调用范围：

- 普通前台生成请求适用；客户端要求非流式，但内部仍逐步接收上游事件时，也可适用。
- 后台请求、Deep Research 等 Interaction 后台 agent，以及现有助手路由不适用。
- Build 原生非流式调用不适用，因为它需读取完整回答后才能向调度层发出事件；继续沿用原有 REQUEST_TIMEOUT，不为本功能强制切换上游传输方式。
- 独立图片生成、视频长任务等其他接口本次不扩展。
- 普通生成路径中的图片、语音等模型仍可纳入；首事件超过总期限也会停止。

“全部模型”仅表示上述范围内符合条件的全部模型，不等于所有接口。首字总期限不以竞速开关是否开启为前提。

思考摘要等非错误上游事件算首字；部分 Interaction 路径的空文本增量或引用也可能先到，本次不另做“首个有效正文”检测。网络字节和服务向客户端发送的保活心跳不算首字。

## 首字竞速

- 一次尝试取得账户租约、开始准备请求时计时，准备请求及等待上游首事件均计入，不仅计算 GenerateContent 发出后的等待。
- 原请求达到阈值且尚未收到首字时，在另一个合法候选账户上发备用请求。原请求继续运行，先收到首字的一方继续服务客户端，仍在等待的另一方取消并记为被取代。
- 一个客户端请求最多同时进行两次生成尝试。不因备用请求自身超过阈值而继续增加第三份。
- 仅使用不同账户。取消现有同账户备用回退；账户绑定、资源归属、API key 与模型可用账户等约束不因竞速而放宽。
- 备用账户须有已就绪的 Worker 且有空闲请求槽位，不要求账户完全空闲，仍遵守单账户并发上限。
- 不为竞速现场启动待命账户的 Worker，不增加专用备用账户池，不额外开发为竞速跨账户复制文件。
- 暂无合法备用账户或全局备用并发已满时，原请求继续等待，并重新检查已就绪账户和全局槽位。首字总期限仍照常计时。
- 备用请求出错后在其他合法候选账户补发，非额度失败计入现有换号次数上限，不无限补发；保留现有额度失败不占非额度换号预算的规则。
- 同一请求仍有其他尝试进行时，不额外再启动第三份。请求的换号与补发共用其重试预算。
- 被取代不算失败；正常收到首字后退出竞速，不因正文尚未完成再次触发备用。

## 首字总等待上限

- 从本请求第一次尝试开始计时，换号、备用请求启动和补发不重置。
- 第一次取得账户之前的排队不计入；第一次尝试开始之后的再次排队仍计入。因此它不是整个 HTTP 请求从进入到完成的耗时上限。
- 到期仍无首字时，取消该请求全部生成尝试，向客户端报告超时。不把计时器到期误判为账号认证、代理或 Worker 故障。
- 单纯到达首字总期限不新增账号冷却；竞速冷却与繁忙冷却仍仅由各自触发条件产生。
- 任何尝试先收到首字后解除该上限，后续仍受现有请求期限和客户端取消约束。
- 现有请求期限或客户端取消更早发生时，按更早的限制终止。响应头已写出时使用协议内错误，不声称可以修改已经发送的 HTTP 状态。

## 两类短冷却

### 竞速冷却

- 仅当不同账户的备用请求先收到首字，且原请求仍在等待、随后被取代时，冷却原请求账户。
- 不在达到竞速阈值或启动备用请求时冷却。
- 原请求胜出时不冷却被取消的备用账户；原请求已报错时不因备用请求随后成功再补记竞速冷却。
- 没有成功发出备用请求时，也不因首字阈值而触发竞速冷却。
- 范围为账户 × 通道 × 模型，初始 30 秒，可配置，0 关闭，固定时长不递增。

### 繁忙冷却

- 用户提供的模型繁忙型 HTTP 503、协议错误码 14 触发短冷却，同时保留失败换号行为。
- 不将更广泛的网络错误或所有其他 5xx 自动归为模型繁忙，不把它记录为额度用尽。
- 范围为账户 × 通道 × 模型，初始 10 秒，可配置，0 关闭，固定时长不递增。
- 不依赖竞速开启。修改冷却时长只影响之后的冷却，不追溯改写已有恢复时间。

### 与现有冷却共存

- 两类短冷却独立保留原因和恢复时刻，不覆盖、不缩短原有额度或权限冷却。
- 同一范围可以同时有现有冷却、竞速冷却和繁忙冷却；有效限制共同生效。
- 短冷却到期前，不能被“所有账户额度冷却后的回退选号”绕过。
- 不因其他请求成功而提前解除已写入的短冷却。冷却前取得租约的其他请求继续执行，成功完成也不清除这些短冷却。
- 两类短冷却均进入现有冷却列表，能够分别看到原因和恢复时间，并可手动清除。清理短冷却不误删其他原因的冷却。
- 绑定请求沿用现有冷却调度规则：指定账户请求按冷却排队规则处理，文件请求保留原有失败后复制与换号机制。不能以绑定条件绕过有效短冷却。

## 配置生效方式

- 保存后立即用于新请求，不要求重启生成服务。
- 新请求使用开始时取得的一份策略快照，正在进行的请求沿用原有阈值、模型范围、总期限与冷却时长。
- 全局备用并发上限调整后约束之后的备用启动。调低时不取消已经运行的备用请求；活动数降到限制以下后才放行新的备用请求。
- 修改或关闭冷却设置不追溯修改已有冷却；需要提前解除时使用手动清除。
- 页面和配置说明明确各开关独立、0 的语义、全部模型的排除范围，以及首事件与正文首字的差别。

## 升级前基线与实现约束

以下记录实现前的行为，供后续与上游同步时比较：

- 现有竞速阈值和模型列表需要重启生成服务才生效；其他请求策略已经存在保存后立即更新的路径。
- 现有竞速每请求最多一个备用，不补发；不同账户要求完全空闲，找不到时可能用同账户槽位；全局上限写死为 4。
- 现有冷却记录不是多原因独立容器；虽然能保留更长冷却，但可能吞并短原因，且回退限制不独立展示。
- 现有成功清理按租约开始时间清除同范围冷却，需要保证新增短冷却不受这种成功清理影响。
- 新模型选择不能使用空列表隐式代表全选，否则会破坏已有配置含义。

## 验收场景

1. A 等待超过 20 秒后，已就绪且仍有空槽的 B 收到备用请求；不要求 B 完全空闲，不超过其并发限制。
2. B 先出首字，A 被取消，A 对应范围出现 30 秒竞速冷却；A 上其他进行中的请求不被取消。
3. A 先出首字，B 被取消，不产生竞速冷却；同账户不竞速。
4. B 报错时可以补 C，但不突破并发数、合法候选账户范围和请求重试预算。
5. A、B 都不出首字时，首次尝试起 60 秒取消全部；换号、排队、补发均不重置。
6. 没有合法备用账户、全局备用已满或竞速关闭时，首字总期限仍独立生效。
7. 模型繁忙型 503 产生 10 秒短冷却并继续现有失败处理；其他 5xx 不误归类。
8. 额度与短冷却叠加时原因可见、互不覆盖；额度回退、并发成功不能提前绕过短冷却，手动清除不会误删其他原因。
9. 后台任务、Build 原生非流式及独立长任务接口不被新增竞速和 60 秒期限误伤。
10. 设置保存后新请求使用新值，进行中的请求保持原策略；全局上限调低不取消已启动备用。
11. 首字之后的正常长回答、长思考不受首字计时器终止；客户端取消与现有请求超时仍正常工作。

## 实现与验证

- 请求策略快照与可撤销首事件期限分别集中在 `internal/app/generation_policy.go`、`first_event.go`；首事件到达点即撤销计时，不等竞速仲裁线程处理。
- 独立短冷却存入运行态的 `short_cooldowns`，按通道、模型、原因隔离。旧版本严格解析运行态，降级前必须停服务并恢复升级前备份，或仅移除新字段；冷却过期不自动恢复旧格式兼容。
- Build 模式由缓存三态查询与实际调用 observer 共同确认；未知备用在真正解析模式后若为 native，会在发送生成 RPC 前拒绝，不强制改变原路由。
- 离线测试覆盖双向胜出、失败补发、全局并发热调整、账号绑定、两类冷却叠加、旧租约、持久化、真实 Build 模式与公开 HTTP 504/错误遮蔽。
- `go test ./...`、相关四包完整 `-race`、`go vet ./...` 已通过；前端 typecheck、lint、format:check 和 build 已通过。macOS 链接器仅报告既有重复 `-lc++` 警告。
